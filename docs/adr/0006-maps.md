# ADR 0006: maps and pins

Status: proposed for 2.7.0.

## Decision

`world` and `location` notes may have a `map` field containing a wikilink to an image in the vault. The map owner may also have `pins`, a list of objects with `note`, `x`, and `y`. `note` is a wikilink to any game note. `x` and `y` are fractions of the image width and height between 0 and 1, written to four decimal places. A note may appear on several maps. Pins belong only to the note that owns each map.

These fields are additive to the note contract in ADR 0004. Old notes need no migration. The plugin writes `map` and `pins` only when the GM chooses an image, attaches a note, moves a pin, or removes a pin. It uses Obsidian frontmatter updates and does not read or change note bodies.

| `type` | New fields |
| --- | --- |
| `world` | `map`, `pins` |
| `location` | `map`, `pins` |

## Layout

Images may live anywhere in the vault. `Library/Assets/` is the recommended folder. Nested locations follow ADR 0005: a location with child places can be a folder note at `Locations/<place>/<place>.md`, with child notes inside that folder. The `location` field on a child links to its parent place. A world map can link to a city map, and a city map can link to a district map.

## Consequences

The map view stores its owner note path in view state. Pins survive image resizing when the replacement keeps the same aspect ratio. Missing linked notes remain visible as grey pins until removed. Map editing is off by default.
